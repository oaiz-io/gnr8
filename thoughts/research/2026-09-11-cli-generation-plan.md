# Implementation plan: a generated CLI on the Python SDK target

Companion to [`2026-09-11-cli-generation.md`](2026-09-11-cli-generation.md).
Target release: **0.15.0** — additive and opt-in. No existing pipeline changes behaviour, no
generated byte moves unless a user adds one method call, and there is no second way to get a CLI.

Two rules govern every decision below, carried verbatim from the research doc because they are the
standard this plan is held to:

> Do not weaken or reinterpret the CLAUDE.md invariants. If a proposed mechanism brushes an
> invariant, say so explicitly and show how the design stays clean.

> verify every product claim in code — the brief's product facts are claims, not truth.

Acting on the second rule, **three claims carried forward from the research doc did not survive a
second reading of the checkout and are corrected here**:

| Research doc said | This checkout says |
|---|---|
| the builder method is `.with_cli("bookstore")` | `grep -c 'pub fn with_' crates/gnr8-sdk/src/sdk/builtins.rs` returns **0**. The entire builder surface uses bare noun setters (`.module()`, `.to()`, `.docs()`, `.package()`, `.layout()`) and `without_*` only as a negation (`without_docs` `builtins.rs:2431`, `without_contract_tests` `:2469`). The method is **`.cli("bookstore")`**. |
| the CLI must decide which security alternative to use | It must not, and it must not be allowed to. The emitted Python client already owns that rule: `_select_auth_alternative` (`crates/gnr8-core/src/pysdk/emit.rs:1600-1636`) walks the operation's alternatives in order, takes the first fully-satisfied one, and raises `AuthConfigurationError` when none is. A CLI-side selector would be a second derivation of one fact (rule 3). |
| the credential is passed as the client's `api_key=` argument | `api_key` is the client's catch-all (`pysdk/emit.rs:1788`). The precise input is `api_keys: Optional[dict[str, str]]` (`:1544`), looked up by **scheme id first** (`:1616`), with `bearer_token` (`:1549`) and `basic_auth: Optional[tuple[str, str]]` (`:1554`) beside it. The CLI populates the per-scheme forms and never the catch-all. |

---

## 0. The one-sentence contract

> `PySdk::new()…cli("bookstore")` emits exactly one additional deterministic file,
> `<sdk dir>/cli.py` — an `argparse` command tree derived from the same `ApiGraph` the client is
> derived from, importing that client, resolving each security scheme's credential from one named
> environment variable **or** one user-configured helper command, printing JSON on stdout and
> diagnostics on stderr — and it adds no dependency the SDK did not already have.

---

## 1. Scope of the first slice

The repository's own guardrail is F-007, *"Keep the first implementation small. Avoid plugin systems,
macro APIs, graph databases, or multi-language runtime machinery until a vertical slice proves the
shape"* (`thoughts/FEATURE.md`). This plan is one language, end to end, and extracts nothing shared
until a second language pushes on it.

| In the slice | Out of the slice (with §11 reasons) |
|---|---|
| `PySdk::cli(name)` builder option | `GoSdk::cli` / `TsSdk::cli` |
| `<sdk dir>/cli.py`, argparse, stdlib-only | a neutral `CommandPlan` IR |
| command tree from `op.group` + `op.id` | any command-naming config surface |
| one `--flag` per param, typed, `choices`, tri-state booleans | positional arguments |
| `--body` / `--body-file` (with `-` = stdin) | a body shorthand grammar |
| credential env var + credential-helper indirection | OAuth2/OIDC flows, token caching |
| `--base-url`, `--json`-shaped stdout, exit codes 0/1/2 | `--plain`, tables, field projection |
| `[project.scripts]` entry point in the emitted `pyproject.toml` | shell completion |
| pagination `--limit`/`--all` where `PaginationPolicy` exists | inferring pagination |
| collision detection as a typed error | any auto-rename table |

## 2. The builder surface, and where its config lives

### 2.1 The method

```rust
.target(
    PySdk::new()
        .module("example.com/bookstore/sdk")
        .to("generated/sdk")
        .cli("bookstore"),
)
```

`PySdk` is `crates/gnr8-sdk/src/sdk/builtins.rs:2345-2356`; `PySdk::new` is `:2360`. One field is
added, in the same shape as `contract_tests` (`:2354-2355`):

```rust
#[serde(default, skip_serializing_if = "Option::is_none")]
pub cli: Option<SdkCli>,
```

and one builder method beside `without_contract_tests` (`:2469`):

```rust
/// Emit a command-line client for this API beside the generated package, invoked as `<name>`.
#[must_use]
pub fn cli(mut self, program: impl Into<String>) -> Self {
    self.cli = Some(SdkCli::new(program));
    self
}
```

`Option` rather than a `bool` + separate name, because the program name is the fact that turns the
option on; two fields would let `cli_enabled = true, cli_name = ""` exist. No `without_cli()` is
added — absence is off, and a negation for an opt-in option would be a second spelling of the same
state.

**Why opt-in when `contract_tests` defaults to on.** A contract test needs no name and is invisible to
a library consumer. A CLI needs a program name, which neither the graph nor `PySdk` holds, and it puts
an `argparse` command tree into a package some consumers only want as a library. The fact is stated
once, in the one place it can be.

### 2.2 Where `SdkCli` lives

New file `crates/gnr8-sdk/src/sdk/cli.rs`, a sibling of the existing pure-config modules
`docs.rs` (`SdkDocs`), `layout.rs` (`SdkFileLayout`) and `model_style.rs` (`PyModelStyle`).

```rust
/// Configuration for a generated command-line client emitted beside a generated SDK.
///
/// This is the CLI gnr8 GENERATES for the user's API. It is unrelated to gnr8's own
/// `gnr8 init` / `generate` / `watch` command surface.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct SdkCli {
    /// Program name — `argparse(prog=…)` and the `[project.scripts]` key.
    pub program: String,
}
```

One field today. It is a struct rather than a bare `String` so that a later addition (a paging cap, a
credential-helper default) does not change the field's type and therefore the serialized declaration
shape, which crosses the host↔worker frame boundary (`crates/gnr8-sdk/src/sdk/stage.rs:1-10`).

The type is re-exported from `crates/gnr8-sdk/src/sdk/mod.rs` alongside `SdkDocs`/`SdkFileLayout`, so
`use gnr8::sdk::prelude::*;` reaches it. `PySdk` is already in the prelude, so a user who never calls
`.cli(…)` sees no new name.

**Validation, at declaration time and again at generation time.** `program` must be non-empty, must
kebab-normalize to a non-empty ASCII `[a-z0-9-]+`, and must not begin with `-`. `SdkCli::new` cannot
return a `Result` without breaking the builder chain style used everywhere else, so the check lives in
the exec path and returns `CoreError::Config` — the same placement `GoSdk`'s `sdk_package` uses for an
unusable module path (`crates/gnr8-core/src/sdk/builtins.rs:3521`).

## 3. Naming: one derivation, shared, in the module that already owns naming

Everything a CLI spells is a re-casing of a fact the SDKs already name. Research §1.5 established that
all three SDK emitters name an operation by re-casing `op.id` and nothing else — `exported(&op.id)`
(`crates/gnr8-core/src/gosdk/emit.rs:93`), `snake(&op.id)` (`pysdk/emit.rs:237`), `camel(&op.id)`
(`tssdk/emit.rs:75`) — all over the one shared tokenizer `split_words`
(`crates/gnr8-core/src/sdk/emit_common.rs:27`), which already handles the acronym-plural case
(`plural_acronym_s`, `:73`).

The CLI is the fourth casing. It goes in `emit_common.rs`, the module that already owns `split_words`,
`file_stem` (`:85`) and `kebab_stem` (`:522`) — **not** a new `naming.rs`, because a second naming home
is how two derivations of one name start.

| New helper | Body | Why not an existing one |
|---|---|---|
| `pub(crate) fn kebab(name: &str) -> String` | `split_words(name).map(lowercase).join("-")` | `kebab_stem` (`:522`) is `file_stem(name).replace('_', "-")` and is documented as a *file* stem; it injects `value`/`value_` prefixes for empty and digit-leading inputs (`:85-101`). Command names must not silently become `value-...`; they must fail. |
| `pub(crate) fn command_name(op: &Operation) -> String` | `kebab(&op.id)` | — |
| `pub(crate) fn command_group(op: &Operation) -> Option<String>` | `op.group.as_deref().map(kebab)` | **not** `operation_group_name` (`:530`), which substitutes `"default"` for `None`. A literal `default` command level would be emitted for every ungrouped API — and both shipped Python examples are entirely ungrouped (`examples/{fastapi,flask}-bookstore/generated/gnr8.graph.json`, every operation's `group` is absent). |
| `pub(crate) fn flag_name(param: &Param) -> String` | `kebab(&param.name)` | the wire name stays `param.name`; only the spelling is re-cased, exactly as `safe_ident` does for Python identifiers (`pysdk/emit.rs:273-283`: *"The WIRE name … is NEVER passed through this"*) |
| `pub(crate) fn screaming_snake(value: &str) -> String` | **moved** from `pysdk/emit.rs:242` | env-var names are needed by any future language's CLI; leaving it in `pysdk` would mean copying it |

`screaming_snake` moving out of `pysdk/emit.rs` is a pure relocation with a re-export
(`pub(crate) use crate::sdk::emit_common::screaming_snake;`) so the ~6 existing call sites and the
unit tests at `pysdk/emit.rs:3480-3487` are untouched.

### 3.1 The command tree rule

**A group level is emitted for an operation iff `op.group` is `Some`.** Ungrouped operations sit
directly under the program. One rule, applied per operation, no global mode switch:

```
examples/fastapi-bookstore  (every op ungrouped)   examples/bookstore   (every op group="books")
  bookstore list-books                               bookstore books list-books
  bookstore create-book                              bookstore books create-book
  bookstore get-book                                 bookstore books get-book
  bookstore update-book                              …
```

This is the same shape restish documents for tag layout (*"Untagged operations remain directly under
the API command"*), arrived at independently because `op.group` is `Option<String>`
(`crates/gnr8-sdk/src/graph.rs:517`) and the honest reading of `None` is "no level", not "a level
called default".

### 3.2 Collision detection — three classes, all hard errors

The precedent is exact. `pysdk/emit.rs:2197-2214` seeds a `used_args` set with `RESERVED_ARGS`
(`:264`) and a `reserve` closure returns `CoreError::SdkGen` naming the operation and the colliding
identifier; `check_unique_model_file_names` (`emit_common.rs:472`) does the same for file stems. The
CLI adds one function in `emit_common.rs` with the same shape:

```rust
pub(crate) fn check_cli_names(graph: &ApiGraph, program: &str) -> Result<(), CoreError>
```

| Class | Example | Result |
|---|---|---|
| two operations kebab to one command in one group | `getBook`, `get_book` → `get-book` | `CoreError::SdkGen` naming both operation ids |
| a top-level command collides with a group name | ungrouped op `books` + group `books` | `CoreError::SdkGen` naming both |
| a flag collides with a reserved global | a param named `json`, `help`, `version`, `base-url`, `limit`, `all`, `body`, `body-file` | `CoreError::SdkGen` naming the operation, the parameter, and the global |

Reserved globals are one `const RESERVED_FLAGS: &[&str]` beside `RESERVED_ARGS`. **No auto-rename
table.** Research §3.1 recorded that `awscli/customizations/argrename.py` carries ~89 renames for
exactly these collisions; a rename invents a second name for one fact (rule 0.2), so the resolution is
the user's — `RenameOperation` (`builtins.rs:1740`) or a source change.

`check_cli_names` runs **before** any text is emitted, so a colliding graph fails generation rather
than producing a shadowed flag. This is strictly earlier than the only duplicate check that exists
today, `graph_artifact.rs:93-99`, which runs after every target has generated
(`crates/gnr8-core/src/pipeline/mod.rs:425-431`).

### 3.3 Operations that are not commands

`Response.body_kind` (`crates/gnr8-sdk/src/graph.rs:595-601`) already distinguishes `"json"`,
`"binary"`, `"sse"`, `"empty"`. An operation whose success response is `"sse"` is **not emitted as a
command** — a streaming response has no terminating JSON document to print. Because `Cx` carries no
diagnostics channel (it is `{ project_root }` and nothing else, `crates/gnr8-sdk/src/sdk/mod.rs:73-76`),
a target can only hard-error or stay silent. Silently dropping a command would be the worse failure, so
this is a `CoreError::SdkGen` naming the operation and telling the user to drop it from the graph with
a `Transform` if they want a CLI. Research §3.1 recorded that AWS reached the same conclusion by
deleting ~37 commands after the fact; refusing at generation time is the earlier version of the same
decision.

## 4. Credentials: one env var per scheme, or one helper command — never both

This is the owner's requirement, and it has two halves: *"can we get it to nicely support different
auth methods?"* and *"like keyring storage etc etc."*

### 4.1 Different auth methods: already graph-owned, already client-owned

Per-operation auth is a fact the graph carries and the SDK already resolves. Nothing in this plan
re-derives it.

- The graph carries `ApiGraph::security` (`crates/gnr8-sdk/src/graph.rs:78`),
  `security_requirements` (`:81`), `operation_security` (`:84`), and per-operation
  `Operation::security` (`:537`).
- `operation_auth_alternatives(graph, op)` (`crates/gnr8-core/src/sdk/emit_common.rs:179-217`)
  resolves that into `Vec<Vec<OperationAuthScheme>>` — *"outer vector is OR, inner vector is AND"*
  (`:177`) — where `OperationAuthScheme` is
  `ApiKey(OperationApiKeyScheme { id, name, location })` or `Http { id, scheme: Bearer | Basic }`
  (`:164-176`).
- `validate_operation_auth_slots` (`:239-268`) already rejects an alternative whose schemes would
  write the same header or query slot.
- **`_select_auth_alternative` in the emitted client** (`crates/gnr8-core/src/pysdk/emit.rs:1600-1636`)
  picks the first alternative every one of whose requirements has a credential, and raises
  `AuthConfigurationError(operation_id, alternatives)` when none does.

So the CLI's entire auth job is **populating credentials**, and it populates the precise inputs, not
the catch-all:

| Scheme kind | Client parameter | Emitted at | CLI passes |
|---|---|---|---|
| `apiKey` (header or query) | `api_keys: Optional[dict[str, str]]` | `pysdk/emit.rs:1544` | `{scheme_id: secret}` — keyed by **scheme id**, which is the first key the client looks up (`:1616`) |
| `http` `bearer` | `bearer_token: Optional[str]` | `:1549` | the secret |
| `http` `basic` | `basic_auth: Optional[tuple[str, str]]` | `:1554` | the secret split on the **first** `:` into `(user, password)` |
| — | `api_key: Optional[str]` (catch-all) | `:1788` | **never.** It is the `or` tail at `:1618`; using it would make one credential reachable by two paths |

The generated CLI therefore supports exactly the auth methods the SDK supports, automatically, with no
CLI-side matrix — and gains new ones for free if the SDK's ceiling moves.

**The ceiling, stated plainly.** `supported_security_schemes`
(`crates/gnr8-core/src/sdk/emit_common.rs:297-327`) accepts `apiKey` in `header`/`query` and `http`
`bearer`/`basic`, and returns `unsupported_security_scheme_error` for anything else — no `oauth2`, no
`openIdConnect`. A CLI over an OAuth-protected API cannot acquire a token itself. §4.3 records why the
helper path makes that *survivable* without widening gnr8's emission surface, and §11 keeps the flow
itself out of scope.

### 4.2 Resolution: one source, selected by configuration, not by availability

Two environment variable names per program, both derived, never configured:

```
credential:  {SCREAMING_SNAKE(program)}_{SCREAMING_SNAKE(scheme.id)}    e.g. BOOKSTORE_API_KEY_AUTH
helper:      {SCREAMING_SNAKE(program)}_CREDENTIAL_HELPER
```

`screaming_snake` is the relocated `pysdk/emit.rs:242` helper (§3), so `ApiKeyAuth` → `API_KEY_AUTH`
through the same `split_words` tokenizer everything else uses.

**The resolution rule, which is a mode selector and not a fallback:**

> If `{PROG}_CREDENTIAL_HELPER` is set and non-empty, the helper is **the** credential source for every
> scheme and the per-scheme variables are not read at all. If it is not set, the per-scheme variables
> are **the** source and no subprocess is ever spawned. In either mode a missing credential is a
> missing credential — it never slides to the other mode.

This brushes CLAUDE.md rule 3, and the plan says so rather than hiding it. Rule 3 forbids *"try
strategy A; on failure fall back to strategy B"*. What is forbidden is recovery-on-failure; what is
here is a mode chosen before any lookup happens, with exactly one path inside each mode. The
distinguishing test is behavioural and testable: **a helper that exits non-zero produces an error, not
an environment-variable read.** That assertion is in the test matrix (§10, `cli_helper_failure`), which
is what keeps the distinction from being a word game.

Rule 3 governs how *gnr8* derives facts; this is a generated program's runtime behaviour. It is held to
the rule anyway, because a generated program that fails over between credential sources is exactly as
hard to debug as a generator that does.

### 4.3 The helper contract

Git solved this problem — the storage backend is a program, not a library — and gnr8 takes the idea
without taking the protocol. This is CLAUDE.md rule 0's *"steal freely; never be compliant"* line: gnr8
does not read `.gitconfig`, does not implement git's `credential` key-value protocol, does not name its
variable `credential.helper`, and would not have to change if git changed tomorrow.

```
invocation : argv = shlex.split($PROG_CREDENTIAL_HELPER) + [scheme_id]
             shell=False, stdin=DEVNULL, timeout=10s, cwd inherited
success    : exit 0 and a non-empty first line of stdout
secret     : that first line, with the trailing newline stripped
failure    : non-zero exit, empty stdout, missing executable, or timeout
             -> stderr message naming the helper, the scheme id and the exit reason; exit 1
```

Everything in it is Python standard library — `shlex`, `subprocess`, `os.environ` — so CLAUDE.md rule 2
(*"keep generated Go, Python, and TypeScript SDKs standard-library-only"*) holds. **No `keyring`
import is emitted, ever.** `keyring` is third-party, and emitting it would put a dependency in the
user's package that gnr8 chose. The user picks the backend at runtime:

```sh
export BOOKSTORE_CREDENTIAL_HELPER='security find-generic-password -w -s bookstore'   # macOS Keychain
export BOOKSTORE_CREDENTIAL_HELPER='op read op://vault/bookstore/token'               # 1Password
export BOOKSTORE_CREDENTIAL_HELPER='gh auth token'                                    # GitHub
export BOOKSTORE_CREDENTIAL_HELPER='pass show bookstore/api'                          # pass
```

gnr8 emits zero lines that know any of those exist.

Four properties the contract is designed for, each one a test in §10:

1. **The secret never reaches any `argv`.** It arrives on the helper's stdout. The only thing on the
   helper's command line is the scheme id, which is public (it is in the OpenAPI document). There is
   no `--api-key` flag at all — clig.dev: *"**Do not read secrets directly from flags.**"*
2. **`shell=False`.** `shlex.split` produces a real argv; no `sh -c`, so a scheme id can never be
   interpolated into a shell.
3. **A helper failure is a diagnostic, not a traceback.** `main()` catches `subprocess` errors and
   `AuthConfigurationError` and writes one line to stderr. `sys.tracebacklimit` is never touched; the
   handler is a plain `except` around the dispatch.
4. **Nothing is cached.** The helper runs once per invocation per scheme actually needed. A token cache
   is state on disk with an expiry rule, which is a product, not a slice (§11).

### 4.4 The error message, which is the whole UX

`AuthConfigurationError` carries `operation_id` and `alternatives: list[list[str]]` of scheme ids
(`examples/fastapi-bookstore/generated/sdk/errors.py`, class `AuthConfigurationError`), and is already
exported from the package root (`__init__.py`, `__all__`). The CLI catches it and maps the scheme ids
back through the same `credential_env_var` derivation, so the message names the exact variables:

```
bookstore: no credentials configured for `get-book`
  set one of:
    BOOKSTORE_API_KEY_AUTH
    BOOKSTORE_BEARER_AUTH
  or set BOOKSTORE_CREDENTIAL_HELPER to a command that prints the secret
```

That mapping is emitted as a literal table in `cli.py` (scheme id → env var), computed in Rust at
generation time. It is not re-derived at runtime, so there is one derivation and it is the Rust one.

## 5. Packaging

### 5.1 What is emitted today

`examples/fastapi-bookstore/generated/sdk/pyproject.toml`, verbatim:

```toml
[build-system]
requires = ["setuptools>=68", "wheel"]
build-backend = "setuptools.build_meta"

[project]
name = "sdk"
version = "0.1.0"
requires-python = ">=3.9"
dependencies = ["pydantic>=2"]

[tool.setuptools]
packages = ["sdk"]

[tool.setuptools.package-dir]
"sdk" = "."
```

It is emitted when `PySdk::package_metadata` is true (default, `builtins.rs:2368`), and its `name`
comes from `SdkPackageMetadata::registry_name` or, unset, the module's last segment
(`SdkPackageMetadata::new` doc, `builtins.rs:2626-2627`: *"targets derive package name from their
module/import path and use version `0.1.0`"*).

### 5.2 The addition

When `cli` is `Some`, three lines are appended:

```toml
[project.scripts]
bookstore = "sdk.cli:main"
```

The key is `SdkCli::program`; the value is `{python package}.cli:main`, where the package name is the
existing `sdk_package(module)` derivation (`crates/gnr8-core/src/sdk/builtins.rs:3521`) — the same one
`PySdk` already uses for `[tool.setuptools] packages`, so there is no second derivation.

That is the whole packaging story, and it is the reason Python is first. Research §1.8 established that
`Artifact` is `{ path: String, text: String, … }` with **no file mode**
(`crates/gnr8-sdk/src/sdk/mod.rs:94-107`), so gnr8 cannot emit anything directly executable. An entry
point sidesteps that entirely: the installer writes the executable shim, not gnr8.

| How the user runs it | Requires |
|---|---|
| `python -m sdk.cli --help` from `generated/` | nothing — works the instant the file is written |
| `pipx install ./generated/sdk` → `bookstore --help` | `[project.scripts]` |
| `uv tool install ./generated/sdk` → `bookstore --help` | `[project.scripts]` |

**One honest caveat to document, not to fix here.** The default distribution name is the module's last
segment, so an unconfigured project installs a distribution literally called `sdk`. A user who wants
`pipx install bookstore-sdk` sets `.package(SdkPackageMetadata::new().registry_name("bookstore-sdk"))`
— an option that already exists (`builtins.rs:2635`). `.cli(…)` does not set it, because inventing a
distribution name from a program name would be a second derivation of a fact the user already has a
method for.

### 5.3 Go and TypeScript, recorded so the slice is not a dead end

Not built here (§11), but the shape is fixed so a later slice does not relitigate it:

- **Go** — `<dir>/cmd/<program>/main.go`, `package main`. It cannot live beside `client.go` because a
  Go directory is one package. `go build ./cmd/<program>` or `go install` gives a single static binary,
  which is the best distribution story of the three; the cost is hand-emitting subcommand dispatch and
  a help renderer, because `flag` has neither (research §4.2).
- **TypeScript** — `package.json` `"bin"`, pointing at a compiled entry. Blocked today: the emitted TS
  SDK is typechecked with `tsc --noEmit --strict --lib es2022,dom` (`Makefile:53-54`) and grepped for
  banned imports (`crates/gnr8-core/tests/tssdk_compile.rs:374`), and a CLI needs `node:util` /
  `node:process`, which that lib set does not have. Changing a shipped gate is a separate decision.

## 6. What `cli.py` contains

One file, five sections, emitted in a fixed order. Everything is `format!`/`writeln!` into a `String`
— the same mechanism `pysdk/emit.rs` already uses, and no template engine, per phase-3 `D-05`
(`.planning/milestones/v1.0-phases/03-openapi-and-go-sdk-generation/03-CONTEXT.md`: *"No heavy
template-engine dependency; a small internal templating approach is fine"*).

```python
# 1. imports — stdlib + the sibling package, nothing else
from __future__ import annotations
import argparse, json, os, shlex, subprocess, sys
from typing import Any, Optional
from .client import Client
from .errors import ApiError, AuthConfigurationError

# 2. generation-time constants — the scheme-id → env-var table (§4.4)
_PROGRAM = "bookstore"
_DEFAULT_BASE_URL = "http://localhost:8000"
_CREDENTIAL_ENV = {"ApiKeyAuth": "BOOKSTORE_API_KEY_AUTH"}
_HELPER_ENV = "BOOKSTORE_CREDENTIAL_HELPER"

# 3. credential resolution (§4.2/§4.3) — ~30 lines, identical in every generated CLI
def _resolve(scheme_id: str) -> Optional[str]: ...

# 4. one handler per operation, and the parser that builds it
def _cmd_get_book(client: Client, args: argparse.Namespace) -> Any:
    return client.get_book(book_id=args.book_id, fmt=args.fmt)

def _build_parser() -> argparse.ArgumentParser: ...

# 5. main()
def main(argv: Optional[list[str]] = None) -> int: ...
if __name__ == "__main__":
    sys.exit(main())
```

### 6.1 The parser, per the research doc's mapping table (§4.3 there)

| Emitted | From | Verified at |
|---|---|---|
| `prog=` | `SdkCli::program` | — |
| top-level `description=` | `graph.title`, `openapi_metadata.description` | `graph.rs:72`, `:165` |
| `--version` action | `openapi_metadata.version` | `graph.rs:162` |
| group subparser | `command_group(op)` when `Some` | `graph.rs:517` |
| command subparser | `command_name(op)` | `emit_common.rs:27` tokenizer |
| `help=` / `description=` | `operation_prose(op, …)` | `emit_common.rs:1174` |
| `--flag` per param | `flag_name(param)`, all four locations | `graph.rs:521`, `pysdk/emit.rs:2647` |
| `required=True` | `param.required` | `graph.rs:556` |
| `type=int` / `type=float` | `Type::Primitive(Prim::Int{..} \| Float{..})` | `facts.rs:461-486` |
| `choices=[…]` | `Type::Enum`, or `Type::Named(id)` → that `Schema`'s `body` | `facts.rs:378`, `graph.rs:681` |
| `action="append"` | `Type::Array(_)` | `facts.rs:365` |
| `default=` | `param.default: LiteralValue` | `graph.rs:561`, `facts.rs:327` |
| `--body` / `--body-file` | `op.request_body`, `request_body_required` | `graph.rs:524`, `:527` |
| `--limit` / `--all` | `PaginationPolicy` for this `op.id` | `graph.rs:340-371` |

Three mappings that are not one-to-one, all settled in the research doc and restated here because they
are what the emitter actually has to branch on:

- **Booleans are two flags.** `--verified` (`store_true`) and `--no-verified` (`store_false`) sharing
  one `dest` with `default=None`; the field is sent only when the value is not `None`. An optional
  boolean query parameter has three states and `store_true` collapses two of them. Where
  `param.default` is present, that value is the default and the third state does not exist.
- **Paging parameters stop being ordinary flags.** If `PaginationPolicy` names `cursor_param`,
  `page_param`, `offset_param`, `limit_param` or `page_size_param` for this operation, those parameter
  names are removed from the flag set and replaced by `--limit N` / `--all`; the loop follows
  `next_cursor_field` / increments the page or offset and stops on `termination`
  (`NoNextCursor | EmptyItems`, `graph.rs:384-391`). Research §3.8 rule 4: every surveyed tool
  converged on this, and all of them had to write it by hand against a sidecar. gnr8 has the policy in
  the graph.
- **`--body-file -` means stdin.** POSIX.1-2024 XBD §12.2 Guideline 13. `--body` takes JSON inline;
  `--body-file` takes a path or `-`. Both are `required=True` when `request_body_required` and mutually
  exclusive (`add_mutually_exclusive_group`).

### 6.2 `main()`, and the exit codes

```
0   success                — the success response body, JSON, on stdout
1   ApiError               — "bookstore: 404 not found (book.missing)" on stderr
1   AuthConfigurationError — the §4.4 message on stderr
1   helper failure         — "bookstore: credential helper failed (exit 2)" on stderr
2   usage                  — argparse's own documented code, unmodified
```

`argparse` already exits 2 on a parse error and writes to stderr
([docs](https://docs.python.org/3/library/argparse.html): *"it will print a message to `sys.stderr`
and exit with a status code of 2"*), so the CLI inherits that rather than reimplementing it. `--help`
and `--version` go to stdout and exit 0, which is what the GNU Coding Standards require
([--help](https://www.gnu.org/prep/standards/html_node/_002d_002dhelp.html)).

Output is JSON and only JSON. Pydantic models expose `.model_dump()` and dataclasses expose
`dataclasses.asdict`, so the emitter picks the serializer from `PySdk::model_style`
(`builtins.rs:2349`) — one branch, at generation time, against a fact already in the declaration.
A `body_kind == "binary"` response writes raw bytes to `sys.stdout.buffer` instead.

## 7. Determinism, and why an unrelated source edit rewrites nothing

Nothing new is needed for either property. Both fall out of where the artifact is placed.

**Byte-identical across runs.** `cli.py` is a fold over an already-sorted graph: operations sorted by
`(path, method)` (`graph.rs:61`), params by name (`:521`), schemas by id (`:63`). The scheme-id → env
var table is emitted from a `BTreeMap`. `Artifacts::create` inserts by binary search on path so the
artifact set stays sorted (`crates/gnr8-sdk/src/sdk/mod.rs:257`). No hash iteration, no timestamps, no
`argv[0]`.

**Unchanged bytes are not rewritten.** `plan_writes` (`crates/gnr8-core/src/lifecycle/mod.rs:198`)
classifies a file whose on-disk bytes equal the freshly generated bytes as `WriteAction::Unchanged`
(`:228`) — *"skip the write (no-op, WATCH-01 / D-05: no mtime churn)"* (`:123-125`) — and
`apply_writes` pushes it to `unchanged` with no write (`:332-333`). This is the owner's *"it should not
need to update when surfaces … are not affecting the SDK"* requirement, already implemented, and
`cli.py` inherits it by being an ordinary artifact. `crates/gnr8-core/tests/lifecycle.rs:609`
(`noop_preserves_mtime`) and `crates/gnr8/tests/generate_e2e.rs:450-459` (`"0 written"`) already assert
it; §10 adds one case that asserts it specifically for `cli.py`.

**Full lifecycle for free.** Because `cli.py` is an `Artifacts::create` artifact in the SDK target's
own directory, it inherits manifest ownership, `gnr8 check` drift reporting, `--force` protection for
hand edits, and deletion when `.cli(…)` is removed. This is the ruling from issue #79's design note,
quoted in research §4.1: *"No second ownership mechanism is introduced."*

**Determinism gates it must join.** `make examples-check` (`Makefile:142-155`) runs
`generate --force && check` in all five examples and diffs against a pre-run copy; adding `.cli(…)` to
one example puts `cli.py` under that gate automatically. `cargo test -p gnr8-engine --test determinism`
is in `make gates` (`Makefile:69`).

## 8. Change gating: no new taxonomy, no new flag

Research §4.5 established the result and this plan does not revisit it — it only records what the
implementation must *not* add.

- **No `cli.*` change codes.** The 81 dotted codes in `crates/gnr8-core/src/changes/diff.rs` already
  classify every fact a CLI's surface is built from. A parallel taxonomy over the same facts is the
  two-sources-of-truth defect rule 3 forbids, and it would immediately need a precedence rule against
  the first.
- **No `--cli` flag on `gnr8 changes`.** The clap definition (`crates/gnr8/src/cli.rs:94-112`) keeps
  `--base`, `--exempt-tag`, `--gate-operation`, `--markdown` and gains nothing. Gating stays
  `gating: kind == ChangeKind::Breaking && scope.checked` (`diff.rs:358`), with untagged operations
  gating by default (`thoughts/research/2026-09-03-api-tags-breaking-change-gating.md:§4.1`).
- **No new report field.** `Change.affected_operations` (`diff.rs:124-125`) already names the generated
  SDK operations a finding touches, and a CLI command is `kebab(op.id)` of the same id, so an existing
  report already says which commands moved.

The one thing the implementation *does* owe is a documented statement of the mapping, so a user reading
a change report knows what it means for their CLI. That is a table in `docs/`, not code:

| Change class | Codes | CLI effect |
|---|---|---|
| command tree | `operation.added` (Additive), `operation.removed`, `operation.name.changed`, `sdk.group.changed` | subcommand appears / disappears / renamed / moves group |
| flags | `request.parameter.*`, `request.body.*`, `request.enum.value.*`, `request.type.changed` | a flag appears, disappears, or changes requiredness/domain |
| credential | `security.scheme.*`, `security.operation.*`, `security.global.changed` | which env var the CLI reads |
| output | `response.*` | what is printed and what is an error |
| default host | `document.server.*` (Breaking branch), `document.base_path.changed` | the default `--base-url` |
| **help text only** | the 8 `DocOnly` codes | `--help` prose moves; tree, flags, choices and exit codes untouched |

The last row is the owner's requirement restated as a checkable property, and research §2.3 verified it
code by code — including the three that look like counter-examples (`operation.tags.changed` does not
move a group because grouping reads `op.group`, not the tag set; `document.metadata.changed` clears
`servers` before comparing at `diff.rs:491-494`; `schema.enum.order.changed` moves the order `choices=`
prints, never the set argparse validates).

**A prose-only change is not a zero-diff change** — `cli.py`'s `--help` strings move, exactly as the
SDK's docstrings do (research §2.6). It is a zero-*gate* change. The zero-diff case is the strictly
narrower one: a source edit that leaves the graph identical. Both must be stated in the docs, because
conflating them is the easiest way to make a true claim sound false.

| lint | `ruff check` + `ruff format --check` over the **target** output | `crates/gnr8-core/tests/sdk_lint.rs` | `ruff` (skips if absent) |
| compiles + imports | `python3 -m py_compile`, then `import <pkg>` | `crates/gnr8-core/tests/pysdk_compile.rs` | `python3` (skips if absent) |
| real dispatch | start an `http.server`, run `cli.main([...])`, assert the JSON on stdout | same | `python3` |
| helper failure | `…_CREDENTIAL_HELPER=/bin/false` → exit 1, one stderr line, **no `Traceback`** | same | `python3` |
| no rewrite | a second `generate` over an unchanged graph reports `cli.py` unchanged | `crates/gnr8/tests/generate_e2e.rs` | built binary |
| byte-identical examples | `make examples-check` diffs the committed `cli.py` | `Makefile:142-155` | full |

Two mechanics worth naming because they are already built and must be reused rather than reinvented:

- **Skipping is an early `return`, never `#[ignore]`.** `python_available()`
  (`crates/gnr8-core/tests/pysdk_compile.rs:50-57`) shells `python3 --version` and each of the eight
  tests opens with the same three-line guard (`:788`, `:863`, `:1411`, `:1439`, `:1463`, `:1488`,
  `:1564`, `:1605`). `sdk_lint.rs:138-141` does the same for `ruff`.
- **Synthetic graphs are hand-written JSON deserialized with serde**, not built with struct literals —
  `auth_graph` (`pysdk_compile.rs:216`), `media_graph` (`:341`), `runtime_graph` (`:478`),
  `pagination_graph` (`:697`). `auth_graph` already exists and already carries bearer and apiKey
  operations, so the CLI auth matrix extends a fixture rather than adding one.
- **The real-dispatch test is a Python driver string.** `ROUND_TRIP_DRIVER` (`:909`) binds
  `HTTPServer(("127.0.0.1", 0), _Handler)` on an ephemeral port in a daemon thread (`:940-948`) and is
  written to a file and run by path. The CLI driver is simpler than the client one: because the server
  has a real port, it needs no `opener=` injection — it passes `--base-url http://127.0.0.1:<port>`
  and calls `cli.main([...])` in-process.

### 10.2 Where the tests live, and why that is forced

`.github/workflows/ci.yml:84-87` installs Python 3.13 with `actions/setup-python@v6`, but only for the
matrix entry whose `needs_python` is `"true"` — `gnr8-engine` (`:65-68`). `gnr8-cli` is
`needs_python: "false"` (`:71`). **Every test that needs `python3` must therefore live in
`crates/gnr8-core/tests/` (package `gnr8-engine`), not `crates/gnr8/tests/`.** That is why the real
dispatch and helper-failure cases sit in `pysdk_compile.rs` and only the no-rewrite case — which needs
the built binary and not Python — sits in `generate_e2e.rs`.

New test files are blocking on day one: neither manifest sets `autotests = false`, so
`crates/gnr8-core/tests/cli_emit.rs` is picked up by `make test` (`Makefile:43`), `make gates`
(`Makefile:66-68`) and CI's `rust-tests` job (`ci.yml:110`). By convention it is also added to the
explicit `--test` list at `Makefile:69`.

### 10.3 CI budget

`scripts/check-ci-budget.py` enforces two rules: every job declares `timeout-minutes` at or below 5,
and no workflow runs `make check`. All four existing workflows already comply (`ci.yml:27`, `:37`,
`:56`, `:115`, `:151`). The added cost is bounded by design:

- the toolchain-free tests are string comparisons — microseconds;
- the Python tests reuse the existing temp-dir + `py_compile` + import harness and add one in-process
  `main([...])` call against a loopback server, which the existing round-trip case already shows costs
  milliseconds;
- `ruff` is one extra invocation over one extra directory;
- `make examples-check` gains one file in one example's diff.

Nothing spawns a network call, a package install, or a second interpreter process per test case.

### 10.4 Scope calibration

The closest precedent is commit `e8f439f` / PR #91, which shipped `gnr8 verify` (issue #79) in 0.14.0:
37 files, and it added exactly **two** test files — `crates/gnr8-core/tests/contract_tests.rs` (348
lines, toolchain-free text assertions) and `crates/gnr8/tests/verify_e2e.rs` (297 lines, driving
`env!("CARGO_BIN_EXE_gnr8")`) — while touching no compile, lint, determinism or snapshot test, no
Makefile and no workflow. This plan is deliberately one notch wider (it does extend `sdk_lint.rs` and
`pysdk_compile.rs`) because a CLI is the first emitted artifact that is *executed by a human*, so
"it compiles" is not a sufficient bar.

There is no Python `.snap` to re-accept: `crates/gnr8-core/tests/snapshots/` holds only the Go SDK
snapshot plus graph and OpenAPI snapshots.

## 11. Ships now vs. deliberately deferred

**Ships now:** the `.cli(program)` option on `PySdk`; `SdkCli`; the naming and collision helpers in
`emit_common`; `pysdk/cli.rs`; `[project.scripts]`; the `fastapi-bookstore` example slice with a
committed `cli.py`; the credential env var and helper contract; the test matrix in §10; a
`docs/cli/generated-cli.md` page; a CHANGELOG entry.

**Deferred, with the reason:**

1. **`GoSdk::cli` and `TsSdk::cli`.** Go needs a hand-emitted subcommand dispatcher and help renderer
   because `flag` has neither; TypeScript additionally needs the shipped
   `tsc --noEmit --strict --lib es2022,dom` gate (`Makefile:53-54`) changed, since a CLI needs
   `node:util`/`node:process`. Both are separate decisions.
2. **A neutral `CommandPlan` IR.** `crates/gnr8-core/src/verify/mod.rs:1-16` is the right eventual
   shape — one plan, three renderers — but research §4.7 and F-007 both say extract it *from* a working
   emitter. With one language it would be an abstraction over a single case.
3. **A `gnr8 verify` CLI suite.** It is nearly free and worth doing second, not first. The Python
   harness runs `python3 <harness> <pkg>/__init__.py <pkg_dir> <package> <module_stem>`
   (`crates/gnr8/src/verify.rs:336-347`, spawned by `run_tool` at `:441`), binds the package with
   `importlib` and runs `unittest`. A `cli_test.py` in the same package needs **zero** harness change —
   only a second `ContractTestSuite` (`crates/gnr8-core/src/verify/mod.rs:101-112`) naming it. It is
   deferred only because `ContractTestSuite` is produced by `target_contract_test_suites`
   (`crates/gnr8-core/src/sdk/builtins.rs:4025`) on the engine-private `TargetExec` trait, and adding a
   second suite per target is a change to that shape that deserves its own review.
4. **OAuth2 / OpenID Connect flows.** `supported_security_schemes`
   (`crates/gnr8-core/src/sdk/emit_common.rs:297-327`) rejects both, so the SDK cannot send such a
   credential at all and a CLI cannot invent one. The helper indirection (§4.3) makes this *survivable*
   without widening gnr8's emission surface: an operator points
   `{PROG}_CREDENTIAL_HELPER` at `gh auth token`, `op read`, or any script that performs the flow, and
   the token arrives as a bearer credential — **if** the graph declares an `http`/`bearer` scheme.
   Emitting a browser redirect flow, a device-code poll, or a token cache is a product, not a slice.
5. **Token caching.** State on disk with an expiry rule and an invalidation story. The helper runs once
   per invocation per scheme; that is the correct starting point.
6. **Shell completion.** `argparse` does not generate it, and research §3.7 established that none of
   clig.dev, the GNU Coding Standards or POSIX XBD §12.2 offers any guidance on it. It is the most
   likely first request after release, and it is a second artifact per shell.
7. **`--plain`, tables, field projection.** Output is JSON only (research §4.3). A generator cannot
   know which fields a human wants, and a per-schema column heuristic is exactly the guessing that
   produces churn.
8. **A body shorthand grammar.** `--body` takes JSON and `--body-file -` takes stdin. restish's
   shorthand is genuinely nicer and genuinely a language, with its own parser, its own type coercion
   rules, and its own failure modes.
9. **Positional arguments for required parameters.** restish does this; clig.dev says *"Prefer flags to
   args"* and gives the reason this plan cares about — *"Sometimes when using args, it's impossible to
   add new input without breaking existing behavior."* Flags are what make a new required parameter
   additive for existing invocations.
10. **A warning channel for targets.** §3.3 hard-errors on an `sse` operation because it has no
    alternative: `Target::generate` takes `&ApiGraph`, not `&mut`
    (`crates/gnr8-sdk/src/sdk/mod.rs:458`), `Cx` is one field (`:73-76`), `Artifacts` has no diagnostic
    sink (`:181-193`), and `pipeline::run` clones `ir.diagnostics`
    (`crates/gnr8-core/src/pipeline/mod.rs:344`) *before* targets run (`:355+`). Giving a target a
    "warn and skip" channel would touch the public `Target` trait, all six built-ins and the
    host↔worker protocol. It is a real design fork — and it is also one of the six areas issue #80's
    conformance kit asks for — so it is named here and left for that work, not smuggled in.

**One recount, so it is not re-litigated.** A reviewer questioned the "81 dotted change codes" figure
from research §2.3. Recounted here by splitting `crates/gnr8-core/src/changes/diff.rs` at its
`#[cfg(test)]` boundary (line 2339) and taking distinct literals with a family prefix from the
production region only: **81**, with every code referenced in the test region also present in
production. A count in the fifties comes from missing the 30 codes returned from inside the
`property_code` (`:2025-2048`) and `type_code` (`:2051-2063`) match arms rather than passed directly to
`out.push`.

## 12. Open questions this plan does not answer

1. **Per-parameter help text does not exist, and creating it is an owner decision.** `Param` has no
   description field and the struct's doc comment says why (`crates/gnr8-sdk/src/graph.rs:546-548`:
   *"There is no enum or description — those were annotation-only and have been removed"*). So
   `--genre GENRE` ships with no explanatory sentence. `FieldFact.description`
   (`crates/gnr8-sdk/src/facts.rs:222-223`) exists for schema fields, reaches the OpenAPI target
   (`crates/gnr8-core/src/lower/mod.rs:928-929`), and is read by no SDK emitter. The options are (a)
   ship without it, (b) widen rule 0.1 category 2 to read a parameter's own declaration doc comment —
   a change to a rule whose text says it *"is narrow and stays narrow"* — or (c) surface
   `FieldFact.description` for body fields only. **This plan assumes (a)** and the emitter simply omits
   `help=` on a flag. The same question is open for issue #78's `StaticDocs`, so it deserves one answer
   for both.
2. **Whether `cli.py` should join the bundle instead of the target.** Target-level placement (§W3)
   mirrors the shipped `contract_test.py` and keeps `pysdk::generate`'s three-argument signature
   stable, at the cost that the existing `pysdk_compile.rs` and `sdk_lint.rs` cases — both of which
   build from `pysdk::generate(&graph, "bookstore", &graph.base_path)` (`sdk_lint.rs:142-144`) — do not
   see it, which is why §W3 and §W5 extend them. Bundle-level placement would mean threading
   `Option<&SdkCli>` through `generate_files_with_options`
   (`crates/gnr8-core/src/pysdk/mod.rs:130-303`) and extending `SDK_FILES`
   (`pysdk_compile.rs:45`) and the four name lists at `pysdk/mod.rs:693-800`. The trade is "smaller
   diff, new tests" against "wider diff, existing tests apply." This plan picks the first; a reviewer
   may reasonably pick the second.
3. **The default distribution name.** An unconfigured project installs a distribution literally called
   `sdk` (§5.2). `.cli(…)` deliberately does not set `registry_name`, but whether it should *warn* is
   unanswerable today — a target has no warning channel (deferred item 10).
4. **`docs/reference/public-api.md` has no sync test.** `grep -rn "public-api"` over code, scripts and
   CI returns nothing, so adding `SdkCli` and `PySdk::cli` to the prelude documentation fails no gate.
   It is a manual checklist item in W6, and it will stay one until someone writes that test.
5. **Windows.** Everything here is reasoned on Linux and CI is `ubuntu-latest` only. `python -m` works
   everywhere; `shlex.split` uses POSIX rules, so a Windows credential-helper command line with
   backslashes would be split wrongly. That needs either a documented "POSIX quoting" contract or a
   platform branch — and a platform branch is a second path, so the documented contract is the likely
   answer.

## Addendum, 2026-09-12: the single-file shape was superseded

§6 of this plan specified one file per language — `cli.py` and `cmd/<program>/main.go` — on the
grounds that a first slice should be small. It shipped that way, and the shape did not survive first
contact with a real API: 258 lines for the bookstore's four operations, and tens of thousands for a
218-operation graph, all in one module.

The emitted CLI is now a project in each language's own idiom. Python: a `cli/` subpackage with one
module per concern and `commands/<group>.py` per group, each exposing `register(subparsers)`. Go:
`cmd/<program>/main.go` calling `cli.Run`, with everything else in `internal/cli` — which is Go's own
visibility rule rather than a convention. [Generated CLI](../../docs/cli/generated-cli.md) carries the
authoritative layout.

Three things that plan got right and this change kept: the command tree still derives from the same
graph facts (§6.1's mapping is unchanged), credential resolution is still one shared module rather
than once per command (§4), and the no-rewrite contract still holds — now per file rather than per
blob, which is what made the split safe.

One decision this plan did not anticipate: `pyproject.toml` is rendered from the SDK's file list, and
package discovery reads the `__init__.py` files in it. The CLI had to join that list *before* the
render or a wheel would ship `[project.scripts]` pointing at a module it did not contain.
